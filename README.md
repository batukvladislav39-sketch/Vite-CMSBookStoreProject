# BookAbyss

Система обліку, організації та контролю продажів у книжковому магазині. Редактор керує книгами, сторінками й блоками в адмін-панелі, а відвідувачі бачать актуальний склад і статистику на швидкому адаптивному сайті.

- Сайт: https://vite-frontend-teal.vercel.app
- Адмін-панель: https://payload-cms-backend-one.vercel.app/admin

## Можливості

- Адмін-панель на Payload CMS: додавання й редагування книг, створення сторінок, складання сторінок із блоків перетягуванням.
- Сайт із розділами: головна, Огляд, Склад, Статистика.
- Склад зі статусами («В наявності», «Закінчується», «Немає») і смужкою запасу.
- Власний API-ендпоінт `GET /api/stats`: підсумки по складу рахуються на сервері.
- Адаптивна верстка (телефон, планшет, комп'ютер).
- Обробка станів інтерфейсу: завантаження, помилка, сторінку не знайдено, порожня сторінка.
- Типізація на TypeScript: union-типи, перетини, узагальнені функції, типізовані дані з API.

## Стек

## Локальний запуск

### 1. База даних

Підготуйте порожню базу PostgreSQL. Якщо використовуєте `docker-compose.yml` з папки `cms`, запустіть:

```
cd Landing/cms
docker compose up -d
```

### 2. CMS

```
cd Landing/cms
cp .env.example .env
npm install
npm run dev
```

У PowerShell замість `cp` використовуйте `Copy-Item .env.example .env`. Відредагуйте `.env` (див. таблицю змінних нижче). Адмін-панель відкриється на http://localhost:3000/admin, де потрібно створити першого користувача.

Під час першого запуску Payload може запитати в терміналі, створити таблицю чи перейменувати наявну. Для нових таблиць обирайте `create table`: поки запитання без відповіді, API не обробляє запити. Якщо колекція Pages порожня, функція `seedPages` сама створить сторінки `home`, `overview`, `inventory` і `stats`.

### 3. Клієнт

```
cd Landing/frontend
cp .env.example .env
npm install
npm run dev
```

Сайт відкриється на http://localhost:5173. Додайте кілька книг в адмін-панелі (розділ Books), і вони з'являться на сторінках Огляд, Склад і Статистика.

## Змінні оточення

| Змінна | Де | Опис | Секретна |
|---|---|---|---|
| `DATABASE_URL` | cms | рядок підключення до PostgreSQL, наприклад `postgresql://user:password@host:5432/dbname` | так |
| `PAYLOAD_SECRET` | cms | довгий випадковий рядок для підпису сесій | так |
| `VITE_API_URL` | frontend | адреса CMS без слеша в кінці, наприклад `http://localhost:3000` | ні |

Секрет можна згенерувати командою:

```
node -p "require('crypto').randomBytes(32).toString('hex')"
```

Файл `.env` не комітьте в репозиторій. Змінна `VITE_API_URL` вбудовується в код під час збірки, тому після її зміни клієнт потрібно збирати заново.

## API

| Метод і адреса | Опис | Доступ |
|---|---|---|
| `GET /api/pages?where[slug][equals]=home` | сторінка за slug разом із блоками | відкритий |
| `GET /api/books?limit=100&depth=0&sort=title` | перелік книг | відкритий |
| `GET /api/stats` | підсумки по складу: кількість, вартість, позиції, що закінчуються | відкритий |
| `POST`, `PATCH`, `DELETE /api/pages`, `/api/books` | зміна даних | лише авторизовані |

## Керування вмістом

- Сторінки створюються в розділі «Сторінки» адмін-панелі. Slug визначає адресу: `home` це головна, а будь-який інший slug відкривається за адресою `#/<slug>`.
- Порядок блоків в адмін-панелі збігається з порядком на сайті.
- Щоб додати нову сторінку в меню, додайте посилання `#/<slug>` у навбар і футер у `frontend/index.html`.
- Статус книги залежить від поля `minStock` (за замовчуванням 5): залишок нижче цього значення означає «Закінчується», нуль означає «Немає».

### Як додати новий тип блока

1. Створіть файл блока в `cms/src/blocks/` і додайте його до списку блоків у `collections/Pages.ts`.
2. Додайте тип блока в `frontend/src/types/index.ts` (до `BlockType` і `DashboardWidget`).
3. Напишіть функцію рендеру в `frontend/src/blocks/`.
4. Додайте її в реєстр `frontend/src/blocks/index.ts`. Якщо пропустити цей крок, компілятор покаже помилку.

## Розгортання на Vercel

Репозиторій містить дві частини, тому створюються **два окремі проєкти** Vercel з одного репозиторію.

**CMS**

1. Root Directory: `Landing/cms`.
2. Змінні оточення: `DATABASE_URL` (хмарна PostgreSQL із `?sslmode=require`) і `PAYLOAD_SECRET`.
3. Локальна база з Docker на Vercel недоступна, потрібна хмарна PostgreSQL (наприклад, Neon або Supabase).
4. Схема в робочому середовищі застосовується міграціями. Створіть міграцію командою `npx payload migrate:create initial`, закомітьте папку `src/migrations` і задайте Build Command: `npx payload migrate && npm run build`.

**Клієнт**

1. Root Directory: `Landing/frontend`, Framework Preset: Vite, Output Directory: `dist`.
2. Змінна оточення `VITE_API_URL` зі значенням адреси CMS (з `https://`, без слеша в кінці).
3. Після додавання або зміни змінної виконайте Redeploy.

**Після першого розгортання**

У `cms/src/payload.config.ts` вкажіть реальні адреси та закомітьте зміну:

```
cors: ['http://localhost:5173', 'https://адреса-сайту.vercel.app'],
csrf: ['http://localhost:3000', 'https://адреса-cms.vercel.app'],
```

Також замініть посилання `http://localhost:3000/admin` у `frontend/index.html` на адресу розгорнутої CMS.

## Типові проблеми

| Симптом | Причина | Розв'язання |
|---|---|---|
| Сайт звертається до `localhost:3000`, браузер блокує запит | під час збірки не було `VITE_API_URL` | додати змінну й перерозгорнути клієнт |
| CORS: немає `Access-Control-Allow-Origin` | адресу сайту не додано в `cors` | додати адресу сайту в `cors` і дочекатися завершення деплою |
| 403 при збереженні в адмінці | адресу CMS не додано в `csrf` | додати адресу CMS у `csrf` |
| API не відповідає або відповідає хвилинами | Payload чекає відповіді на запитання про таблиці в терміналі | вибрати `create table` у терміналі CMS |
| Збірка CMS падає на типах | у проєкті лишилися застарілі файли | видалити їх, виконати `payload generate:types` і `npx tsc --noEmit` |
| `Module not found` | файл відсутній або лежить не в тій папці | звірити шлях і назву файлу, очистити `.next` |

## Обмеження та плани

- Колекції продажів і постачання з автоматичним оновленням залишків поки не реалізовані.
- Перелік книг на сайті обмежено 100 записами, пагінації немає.
- Маршрутизація за хешем не оптимальна для пошукових систем.
- Статистика наразі читається публічно; для робочого середовища її варто закрити авторизацією.
- Колекція Media підготовлена для зображень, проте блоки її ще не використовують.
